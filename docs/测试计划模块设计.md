## 1. 需求概述

在已有**项目管理 + 用例管理**基础上新增**测试计划**模块，支撑"按项目组织一次测试执行"的管理诉求：

- **计划归属项目**：一个测试计划属于且仅属于一个项目（`plans.project_id`），项目下可创建多个计划；
- **计划关联用例**：进入计划后，只能从**该计划所属项目**下添加用例；计划与用例之间为**关联关系**，不在计划内复制用例内容（标题/步骤/预期结果等始终以 `testcases` 表为准，实时联查展示）；
- **计划内执行记录**：计划用例（关联行）上记录**测试人、测试结果、结果描述**，用于执行追溯与统计，不反写 `testcases` 表；
- 计划内用例**不区分执行顺序**（关联行按添加时间自然排序），是否需要排序字段留待后续版本评估。

> 与用例管理的关系：用例模块负责用例的**维护与沉淀**（草稿/评审/归档），测试计划模块负责**挑选用例执行并回填结果**。二者解耦，用例的修改实时反映到所有引用它的计划中。

### 1.1 领域名词

| 名词 | 含义 |
|---|---|
| 测试计划（TestPlan） | 一次测试执行的组织单元，归属某个项目，含状态（未开始/进行中/已完成） |
| 计划用例（PlanTestCase） | 计划与用例的关联记录，额外携带测试人/结果/结果描述等执行字段 |
| 候选用例 | 计划所属项目下、尚未加入该计划的用例（添加用例弹窗的可选范围） |

## 2. 功能清单

| 编号 | 功能 | 说明 |
|---|---|---|
| F1 | 计划列表 | 分页 + 筛选（所属项目/状态/关键字）+ 计划内用例数、通过/失败统计 |
| F2 | 新增计划 | 输入名称、所属项目、描述、初始状态（默认未开始）；项目须存在且启用 |
| F3 | 编辑计划 | 修改名称/描述/状态；**所属项目不可变更**（防错） |
| F4 | 删除计划 | 删除计划及其全部计划用例关联（不影响用例本身） |
| F5 | 计划详情 | 查看计划基本信息与所属项目 |
| F6 | 添加用例到计划 | 批量勾选**该项目下、未加入本计划**的用例（候选列表支持关键字搜索） |
| F7 | 计划用例列表 | 展示加入本计划的用例（用例内容实时联查），含测试人/结果/结果描述 |
| F8 | 记录/修改结果 | 填写 测试人 + 结果（四态）+ 结果描述；测试人默认为当前登录用户 |
| F9 | 移除计划用例 | 从计划中移除关联（不删除用例） |

约束规则：

- 计划新增/编辑时，若项目被停用则不允许创建计划；已有用例/计划的停用项目不允许再操作；
- 添加用例仅限**计划所属项目**下的用例，其他项目用例拒绝；
- 同一用例在同一计划内**不可重复添加**（唯一约束）；
- **删除被计划引用的用例**时返回 409 冲突（防止执行记录静默丢失），需先从计划中移除；**删除被计划引用的项目**同理（项目删除校验扩展为"存在用例或计划"）。

## 3. 数据模型设计

### 3.1 ER 关系

```
Project 1 ──── n TestPlan 1 ──── n PlanTestCase n ──── 1 TestCase
                  │                                        │
                  │                                      TestCase 内容不复制，
                  │                                      仅以 testcase_id 关联
                  ▼
               (plan_testcases 关联表)
                  │
                  └─ 关联 users（tester_id，测试人，SET NULL 安全删除）
```

- `plans.project_id` → `projects.id`（CASCADE：删项目级联删计划，删除由"引用校验"拦截，此 CASCADE 为兜底）；
- `plan_testcases.plan_id` → `plans.id`（CASCADE：删计划自动清理关联）；
- `plan_testcases.testcase_id` → `testcases.id`（CASCADE 兜底，删除由"引用校验"拦截）；
- `plan_testcases.tester_id` → `users.id`（SET NULL：用户被删不影响计划用例记录）。

### 3.2 表：`plans`（测试计划）

继承 `BaseModel`：id / created_at / updated_at。

| 字段 | 类型 | 约束/默认 | 说明 |
|---|---|---|---|
| name | String(100) | NOT NULL | 计划名称 |
| project_id | Integer | NOT NULL, FK→projects.id, index | 所属项目（一个计划属于一个项目） |
| description | Text | NULL | 计划说明（测试范围/依据等） |
| status | String(20) | NOT NULL, default 'not_started' | 计划状态：not_started(未开始)/in_progress(进行中)/completed(已完成) |

### 3.3 表：`plan_testcases`（计划用例关联表，含执行记录）

继承 `BaseModel`：id / created_at / updated_at。

| 字段 | 类型 | 约束/默认 | 说明 |
|---|---|---|---|
| plan_id | Integer | NOT NULL, FK→plans.id, index | 所属计划 |
| testcase_id | Integer | NOT NULL, FK→testcases.id, index | 关联用例（内容不复制） |
| tester_id | Integer | NULL, FK→users.id (SET NULL) | 测试人（下拉选择系统用户；记录结果时默认当前登录用户） |
| result | String(20) | NULL | 测试结果四态：pass/fail/blocked/skipped；未执行时为空 |
| result_desc | Text | NULL | 结果描述（失败原因/过程说明等） |

约束与索引：

- `UNIQUE(plan_id, testcase_id)`：同一用例在一计划内唯一；
- 复合索引 `(plan_id, id)` 已由 plan_id 普通索引 + 添加时间排序满足，无需额外索引；
- `updated_at` 在回填/修改结果时自动刷新，作为"最后执行/修改时间"展示。

设计说明：

- **只存关联、不复制内容**：用例标题/模块/优先级/前置条件/步骤/预期结果等字段一律实时联查 `testcases` 返回，保证用例改动即时同步到计划；若历史版本追溯成为硬需求，再引入快照列或执行历史表（`plan_testcase_executions`），本期不做；
- 结果状态为**四态枚举**：`pass`(通过)/`fail`(失败)/`blocked`(阻塞)/`skipped`(未执行)，前端标签配色 绿/红/橙/灰；
- 结果记录支持**覆盖修改**（记录错误可修正，覆盖前值不保留历史）；如需执行历史留痕，后续扩展 executions 子表；
- 计划状态为**生命周期状态**，与用例结果互相独立：completed 只表示本次计划收尾，不锁死用例结果回填（是否禁止回填由前端交互约束，后端不强校验）。

## 4. API 接口设计

统一前缀 `/api/v1`，鉴权：`Bearer Token` + `require_permissions(...)`。全部响应走统一包装 `{ code, message, data }`，列表分页 `{ items, total, page, page_size, total_pages }`。

### 4.1 计划接口（`plans.py`，路由前缀 `/plans`）

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | /plans | plan:list | 分页列表；参数：project_id,status,keyword,page,page_size；每行附 case_count 及 pass/fail 统计 |
| GET | /plans/{id} | plan:detail | 计划详情（含项目编码/名称） |
| POST | /plans | plan:create | 新增计划；body: {name, project_id, description?, status?}；校验项目存在且启用 |
| PUT | /plans/{id} | plan:update | 编辑 name/description/status；project_id 不在更新字段中（不可变更） |
| DELETE | /plans/{id} | plan:delete | 删除计划（级联清理 plan_testcases） |

### 4.2 计划用例接口（挂在 `/plans/{id}` 下）

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | /plans/{id}/testcases | plan:case:list | 计划用例列表；每项=关联行信息 + 用例实时内容（标题/模块/优先级/类型/来源/状态）+ 项目名 |
| GET | /plans/{id}/candidates | plan:case:add | 候选用例分页列表：该项目下**且未加入本计划**的用例；参数：keyword,page,page_size |
| POST | /plans/{id}/testcases | plan:case:add | 批量添加用例；body:{testcase_ids:[]}；校验均属于所属项目；跳过已存在，非法归属报 409 |
| PUT | /plans/{id}/testcases/{ptc_id}/result | plan:case:result | 记录/修改结果；body:{result?, result_desc?, tester_id?}；tester_id 缺省取当前用户 |
| DELETE | /plans/{id}/testcases/{ptc_id} | plan:case:remove | 移除该计划用例关联（不删除用例） |

> 权限粒度说明：计划内"查看"随计划列表/详情（plan:list / plan:detail）即可看到关联用例；此处独立出 `plan:case:list` 是为页面 tab 单独控制。若希望精简，可合并为：查看复用 `plan:detail`、增删复用 `plan:update`、结果回填用 `plan:execute`。**默认按上表细粒度实现**。

### 4.3 响应示例

计划列表项：

## 5. 权限设计

### 5.1 API 权限（Permission 表，追加到 seed）

| 编码 | 名称 |
|---|---|
| plan:list | 计划列表 |
| plan:detail | 计划详情 |
| plan:create | 新增计划 |
| plan:update | 编辑计划 |
| plan:delete | 删除计划 |
| plan:case:list | 计划用例列表 |
| plan:case:add | 添加用例到计划 |
| plan:case:result | 记录测试结果 |
| plan:case:remove | 移除计划用例 |

### 5.2 菜单与按钮（Menu 表）

在既有 `测试管理（/test）` 目录下新增子菜单（新增用例管理之后）：

```
测试管理（directory, path=/test, sort=3）
├── 项目管理（/test/projects, sort=1）
├── 用例管理（/test/testcases, sort=2）
└── 测试计划（menu, path=/test/plans, component=test/TestPlanManage, permission=plan:list, sort=3）
    ├── 新增计划（button, plan:create）
    ├── 编辑计划（button, plan:update）
    ├── 删除计划（button, plan:delete）
    └── （计划详情页内按钮由前端按权限隐藏）
        添加用例（plan:case:add）/ 记录结果（plan:case:result）/ 移除用例（plan:case:remove）
```

### 5.3 角色授权

- `admin`：默认全部权限与菜单；
- `user`：只读授权 `plan:list / plan:detail / plan:case:list`（含进入计划查看用例），不含按钮权限；
- 其他角色：角色管理界面勾选授权，保存触发 `invalidate_policy()` 同步 Casbin。

### 5.4 关联校验（写操作前强制）

| 操作 | 校验 |
|---|---|
| 新增/编辑计划 | project 存在且 is_active=True，否则 400 |
| 添加用例 | 每个 testcase_id 存在且 `testcase.project_id == plan.project_id`，否则 409；已存在则跳过（仍返回成功及实际加入数） |
| 删除用例 | 若存在任何 plan_testcases 引用 → 409"用例已被测试计划引用，请先从计划中移除" |
| 删除项目 | 扩展校验：存在用例 **或测试计划** → 409 禁止删除 |

**添加用例弹窗**：

- 数据源 `/plans/{id}/candidates`（所属项目下未加入本计划的用例），表格多选 + 关键字过滤，勾选后点击确定批量提交 `POST /plans/{id}/testcases`；

**记录结果弹窗**：

- 测试人：下拉选择系统用户（`/users?keyword=` 或复用用户列表接口），默认当前登录用户；

- 结果描述：多行文本域（失败时提示填写失败原因）；已有结果再次打开即为回填模式，保存为覆盖更新。

## 8. 说明与待确认项

1. **删除保护策略**：本设计选择"用例/项目被计划引用时禁止删除（409）"，保证计划执行记录可追溯。若希望放宽（删除用例自动级联清理计划关联），改 `testcase_id` 外键行为即可，需在评审时确认；
2. **结果修改历史**：本期"覆盖式"记录结果，不保留历史；若需审计留痕，后续可新增 `plan_testcase_results` 历史表或在 operation_log 记录；
3. **用例内容变更**：因计划内展示实时联查 testcases，计划建立后用例被编辑，计划内将显示新内容（符合"关联"定位）；如需"按当时版本执行"的快照语义，需引入快照列，待评审；
4. **执行顺序**：按确认结果，本期不引入 sort 字段；后续需要按序执行时再加 `plan_testcases.sort`。
