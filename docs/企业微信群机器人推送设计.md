# 企业微信群机器人推送测试结果 —— 设计文档

## 1. 背景与目标

测试平台的自动化用例执行完成（批量执行 / 定时执行）后，结果只停留在平台内，团队无法第一时间获知。本功能引入**企业微信群机器人**作为通知渠道：

1. 系统管理下新增「企业微信群机器人」模块，支持对群机器人增删查改（含一键发送测试消息）；
2. 测试计划创建/编辑时，可选择平台已有的企业微信群机器人（**多选**）；
3. 该计划发生「批量执行」或「定时执行（含立即执行）」整轮跑完后，自动向已绑定的机器人推送本轮**测试结果统计**。

推送失败不影响用例执行主流程（旁路通知）。

## 2. 总体架构

```
                           ┌──────────────────────────────────────────┐
 执行入口（手动批量/定时）──►│ _execute_cases_sequential 串行执行本轮用例 │
                           └───────────────┬──────────────────────────┘
                                           │ 整轮结束（正常/被终止均结束）
                                           ▼
                     wecom_service.notify_plan_finished(plan_id, ctx)
                                           │ 读取 plans.robot_ids → 机器人列表（enabled）
                                           │ 汇总本轮统计 → 组 markdown
                                           ▼
                               httpx POST 企业微信群机器人 webhook（每机器人一条）
```

- 单条用例执行（`execute`）**不推送**——只覆盖用户要求的两种整轮场景；
- 统计口径按「本轮选中的用例执行后的最新结果」汇总；
- 定时任务自然结束点与手动批量不同，两处分别挂通知（§5 接入点）。

## 3. 企业微信群机器人模块（系统管理）

### 3.1 数据表 `wecom_robots`

| 字段 | 类型 | 说明 |
|---|---|---|
| id / created_at / updated_at | BaseModel | 通用 |
| name | varchar(100) NOT NULL | 机器人名称，如「测试部-质量群」 |
| webhook_url | varchar(500) NOT NULL | 群机器人 webhook（含 key 参数） |
| secret | varchar(255) NULL | 加签密钥（安全设置-加签），**加密存放**（Fernet `ENCRYPTION_KEY`），仅写入不回显 |
| enabled | bool NOT NULL default true | 停用后计划侧不可选、不再推送 |
| description | text NULL | 备注（用途/所属群） |
| created_by | FK users.id SET NULL | 创建人（真实用户 id，复用 `actor_user_id` 语义不需要——本模块仅 JWT 超管向，直接存登录人） |

> 企业微信群机器人能力约束（实现需遵守）：
> - 仅 `markdown` / `text` 两类消息；markdown 单条 **≤ 4096 字节**；
> - 每个机器人限频 **20 条/分钟**（单轮批量只发 1 条/机器人，不会触发）；
> - webhook 泄漏即等于获得向该群发消息的权限，故列表/详情一律**脱敏**（详见 §7）。

### 3.2 权限与菜单（seed_data 幂等增量，仿 `_ensure_api_key_module`）

权限码（模块名统一 `wecom_robot`，连字符风格沿用 `api-key:*`）：

| code | 名称 | 用途 |
|---|---|---|
| wecom-robot:list | 机器人列表 | 管理页列表/详情 |
| wecom-robot:create | 新增机器人 | 新增 |
| wecom-robot:update | 编辑机器人 | 编辑 + 启停 + 发送测试消息 |
| wecom-robot:delete | 删除机器人 | 删除 |

菜单：一级目录「系统管理」下新增二级菜单 **企业微信机器人**，`path=/system/wecom-robots`、`component=system/wecom-robots/index`、`permission=wecom-robot:list`、sort 排到 API 密钥之后；下挂 3 个按钮（新增/编辑/删除）。`seed_data.py` 新增 `_ensure_wecom_module(db)`，增量运行同样生效。

### 3.3 接口（仅 JWT，`require_permissions`；仿 api_keys.py）

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | /api/v1/wecom-robots | wecom-robot:list | 列表（分页 + 关键字 + enabled 过滤），webhook/secret 脱敏 |
| POST | /api/v1/wecom-robots | wecom-robot:create | 新增（webhook 格式校验、secret 加密落库） |
| PUT | /api/v1/wecom-robots/{id} | wecom-robot:update | 编辑；secret 为空表示不改；webhook 变更需二次确认 |
| DELETE | /api/v1/wecom-robots/{id} | wecom-robot:delete | 删除；被计划引用时拒绝并提示 |
| POST | /api/v1/wecom-robots/{id}/test | wecom-robot:update | 发送一条测试 markdown，验证 webhook/加签可用 |
| GET | /api/v1/wecom-robots/options | 仅登录（JWT） | **计划选择下拉专用**：只返回 id/name/enabled，不返回 webhook；无系统管理权限的测试人员也可绑定 |

> `options` 单独放开：机器人 webhook 属敏感配置，但「选择机器人」是计划编辑者的常规操作，二者解耦；管理接口一律 `wecom-robot:*` 权限。

## 4. 计划绑定机器人（多选）

### 4.1 数据结构

`plans` 表新增一列：

```
robot_ids  JSONB  NULL   -- 绑定的企业微信群机器人 id 数组，如 [1, 3]
```

不建多对多关联表：机器人只是「推送目标」，无查询计划的反向需求，JSONB 数组最简。

### 4.2 接口与展示

- `POST /plans`、`PUT /plans/{id}` 的 payload 增加可选字段 `robot_ids: list[int]`；校验：id 必须存在、允许绑定已停用（历史）机器人，但新建时只提供 enabled 的选项；
- `GET /plans/{id}` 与列表响应增加 `robots: [{id, name}]`（解析后的名称，前端 tag 展示）；
- 前端计划抽屉：表单「结果推送」区，多选（`a-select mode=multiple`），数据源来自 `options` 接口，置灰展示已停用项；
- 批量执行/定时任务**创建时快照不受影响**：推送永远读「当前」绑定的机器人（与定时任务解耦，不复制到 schedule）。

## 5. 推送触发点

两处整轮结束点，各自读取 `plans.robot_ids` 触发（均旁路、不阻塞、失败只记日志）：

| 场景 | 结束点（现有代码） | 触发方式标记 |
|---|---|---|
| 批量执行（手动） | `plan_service.execute_auto_cases` 创建的后台 task done 回调（或 `_execute_cases_sequential` 返回后） | 手动批量 |
| 定时执行 / 立即执行 | `schedule_service._run_schedule_batch` 的 `_finalize_schedule` 处 | 定时执行 |

实现约定：在 `_execute_cases_sequential` 之外、由调用方各自在“整轮结束”处调用 `wecom_service.notify_plan_finished(...)`，避免在串行内核里堆通知逻辑；被用户终止（stop）的半轮执行**也要通知**（统计含被置为 skipped 的未跑用例，让群里知道这轮没跑完）。

通知上下文 `ctx`：`plan_id`、`trigger_type`、`operator_name`、`entries(ptc_ids)`、`started_at/finished_at`、耗时。

## 6. 推送内容设计（已定稿）

### 6.1 统计口径（本轮内）

对 `entries` 覆盖的 ptc，执行结束后取各自最新 `result` 分桶（`ALLOWED_RESULTS`）：

| 桶 | 来源 |
|---|---|
| 通过 pass | result=pass |
| 失败 fail | result=fail |
| 阻塞 blocked | result=blocked |
| 跳过 skipped | 被用户终止/预置 skipped |
| 中断 running | 进程异常退出遗留（极少数，单列出来提醒，不算入通过率） |

**通过率 = pass / (pass + fail + blocked) × 100%**（跳过与中断不计入分母），保留两位小数；无有效执行（分母=0）显示 `-`。

### 6.2 推送内容（markdown 单条）

- **标题**：测试计划名 + 结果概要
- **基本信息**：所属项目、触发方式、发起人（批量=当前用户；定时=任务创建人）、开始/结束时间、耗时
- **执行统计**：用例总数、通过、失败、阻塞、跳过、中断、通过率
- **失败/阻塞明细（最多前 10 条）**：用例标题 + result_desc 摘要（太长截断），帮助群里直接定位问题
- **查看详情链接**：可选项，配置项 `NOTIFY_FRONTEND_URL`（前端首页地址）存在时追加 `计划详情` 链接

企业微信群机器人 markdown 对语法支持有限，**不用表格/emoji 图标排版**，使用纯文本行 + 简单列表 + `<font color>` 着色（info/comment/warning 三档），保证在 PC/手机端都稳定渲染。

### 6.3 渲染样例

```
📋 测试结果：App 回归 v1.0
<font color="comment">本次执行：2 失败 · 18 通过</font>

所属项目：App 项目
触发方式：批量执行（手动）
发起人：张三
执行时间：2026-09-08 19:02:33 ~ 19:05:45（3 分 12 秒）

用例总数：24
<font color="info">通过：18</font>
<font color="warning">失败：4</font>
<font color="warning">阻塞：1</font>
跳过：1 · 中断：0
**通过率：78.26%**

失败/阻塞明细（前 10 条）：
1. [失败] 登录-正确密码登录 — 断言失败：未出现「欢迎页」
2. [失败] 订单-创建订单 — 超时：等待元素 60s
3. [阻塞] 支付-微信支付 — 依赖用例失败

查看完整报告：https://platform.example.com/test/plans/12
```

（“📋”等 emoji 可按需去掉，保持纯文本最低渲染风险。）

## 7. 安全设计

1. **webhook/secret 脱敏**：列表与详情只返回 `masked_webhook`（key 仅保留后 4 位，如 `qyapi...key=****abcd`）；secret 仅 `POST/PUT` 写入（Fernet 加密），任何读接口不回显，编辑时留空=不修改；
2. **推送目标不受信任输入控制**：发送方只接受「计划绑定的机器人 id」→ 服务端查库取 URL，绝不接收前端传来的 URL（防投毒/SSRF）；
3. **删除保护**：机器人被任一计划引用时禁止删除（前端也可先解绑），避免“推送静默失效”；
4. **权限**：管理接口 `wecom-robot:*`；计划侧拉取机器人只读 `options`（仅登录），拿不到敏感字段；
5. **停用保护**：`enabled=false` 的机器人不推送、不出现在下拉可选列表。
