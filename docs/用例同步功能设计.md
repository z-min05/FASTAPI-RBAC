## 1. 需求概述

### 1.1 业务场景

现有流程是「管理端建用例 → 生成 pytest 代码骨架」（[自动化用例文件生成模块设计.md](file:///d:/Users/zhangzhimin/Desktop/test01/fastapi-rbac/FASTAPI-RBAC/docs/自动化用例文件生成模块设计.md)）。实际使用中自动化用例往往已在 pytest 项目中**先写好**，需要反向补齐到管理端，因此新增「用例同步」：

- 在**用例管理**页面增加「同步用例」按钮；
- 点击后扫描所选项目 `auto_root_path` 下的 pytest 测试用例，把尚未入库的用例批量写入管理端；
- 同步为**异步下发**：接口立即返回提示，避免长时间扫描/写库导致前端请求超时。

### 1.2 按钮显示规则

| 场景 | 是否显示「同步用例」 |
|---|---|
| 页面未选择项目 | 不显示 |
| 选择的项目未配置自动化根路径（`auto_root_path` 为空） | 不显示 |
| 选择项目且该项目已配置自动化根路径 | **显示** |

> 用例管理页面进入时会默认选中第一个项目（[TestcaseManage.vue](file:///d:/Users/zhangzhimin/Desktop/test01/fastapi-rbac/FASTAPI-RBAC/frontend/src/pages/test/TestcaseManage.vue#L360-L374)），因此首项目已配置根路径时按钮会出现。
> 按钮同时受权限控制：无 `testcase:sync` 权限的用户不显示。

### 1.3 映射关系

```
项目.auto_root_path → D:\zzm\pytestProject\test_framework_meterbot\tests
           ↓
文件（不含 .py 后缀） → 用例.模块编码（module_code），如 test_login
           ↓
函数名                → 用例.用例编码（case_code），如 test_login_success_01
@allure.title("...")  → 用例.标题（title）
```

以 `tests/test_login.py` 为例：

```python
@allure.title("示例用例-登录功能1")
def test_login_success_01(login_page: LoginPage):
    ...
```

同步后生成一条用例：

| 字段 | 值 | 来源 |
|---|---|---|
| 项目 | 当前所选项目 | 请求参数 |
| 标题 | 示例用例-登录功能1 | `@allure.title` |
| 模块编码 | test_login | 文件名（去 `.py`） |
| 用例编码 | test_login_success_01 | 函数名 |
| 模块 | test_login | 默认值 |
| 优先级 | P1 | 默认值 |
| 类型 | function | 默认值 |
| 来源 | 自动同步 | 默认值 |
| 状态 | draft | 默认值 |
| 预期结果 | 待补充 | 默认值 |
| 前置条件 / 步骤 / 标签 | 空 | 默认值 |

### 1.4 核心约束

| 规则 | 说明 |
|---|---|
| 只增不改 | 已存在的 `(module_code, case_code)` 跳过，不更新标题、不覆盖任何字段 |
| 不复用生成逻辑 | 同步过程**不调用** `generate_automation_file`，绝不反向改写 `.py` 文件 |
| 校验沿用现有规则 | 编码格式用 `validate_codes`；唯一性用现有「同项目下 (module_code, case_code) 唯一」语义 |
| 根路径必须存在 | 项目未配置或路径不存在/不可读时，接口直接返回友好错误，不下发任务 |
| 异步下发 | 接口只做参数校验 + 创建后台任务，立即返回 |

## 2. 数据模型与权限变更

### 2.1 数据库

**无表结构变更、无 Alembic 迁移**：完全复用 `testcases` 表与现有条件唯一索引 `ix_testcases_project_module_code`（`UNIQUE(project_id, module_code, case_code) WHERE module_code IS NOT NULL AND case_code IS NOT NULL`）。

### 2.2 权限与菜单（`scripts/seed_data.py`）

| 类型 | 编码 | 名称 | 说明 |
|---|---|---|---|
| 权限 | `testcase:sync` | 同步用例 | 新增到 `TEST_PERMISSIONS`（`module=testcase`, `action=sync`） |
| 菜单按钮 | — | 同步用例 | 新增到 `TEST_MENUS` 中「用例管理」菜单的 `children`，`sort=6` |

- 现有 `_ensure_test_module(db)` 本身是幂等的（权限按 `code` 查、按钮按 `name+parent+menu_type` 查），**新增条目后无需写新的 ensure 函数**，全新安装与存量库增量执行 `python -m scripts.seed_data` 都会自动补齐；

## 3. 后端设计

### 3.1 文件清单

| 文件 | 类型 | 内容 |
|---|---|---|
| `backend/app/services/testcase_sync_service.py` | 新增 | 扫描解析 + 同步写入 + 异步下发入口 |
| `backend/app/api/v1/testcases.py` | 修改 | 新增 `POST /testcases/sync` 接口 |
| `backend/scripts/seed_data.py` | 修改 | 新增权限与菜单按钮（见 2.2） |

### 3.2 扫描与解析

- 扫描范围：`Path(auto_root_path).rglob("test_*.py")`
  - 排除：`conftest.py`、`__pycache__`、隐藏目录（`.` 开头）、`venv` / `.venv`
  - 结果按路径排序，保证多次同步顺序稳定
- 解析方式：标准库 `ast`（不导入、不执行被测代码，安全性高）
  - 采集**模块顶层** `def test_*` 与 `async def test_*`
  - `case_code` = 函数名
  - `title` = 函数装饰器中第一个 `allure.title("...")` 的字符串参数；没有则回退为函数名
  - 读取失败（文件缺失/编码错误）或 `SyntaxError`：该文件跳过并记录原因，不影响其他文件
- 模块编码合法性：文件名需匹配 `^test_[a-zA-Z0-9_\-]+$`（与 `validate_codes` 一致），否则跳过；用例编码需匹配 `^test_[a-zA-Z0-9_]+$`

> 限制说明：`case_code` 即函数名，与现有执行约定（按 `{module_code}.py::{case_code}` 定位）保持一致，因此**本轮只采集顶层函数**，`class TestXxx` 内的方法不同步（见 §6 待确认项）。

### 3.3 校验与去重（沿用创建/编辑用例的方式）

按 [testcase_service.py](file:///d:/Users/zhangzhimin/Desktop/test01/fastapi-rbac/FASTAPI-RBAC/backend/app/services/testcase_service.py#L216-L232) 的既有规则：

1. `validate_codes(module_code, case_code)` 校验格式（流式：不合法 → 计入 `skipped_invalid`，记录原因，继续下一条）
2. 唯一性：查询同项目下 `(module_code, case_code)` 是否已存在
   - 已存在 → 计入 `skipped_exists`，**跳过**
   - 不存在 → 新增（`TestCase(...)`）
3. 批量处理结束后统一 `commit` 一次

> 与创建/编辑接口的差异：创建/编辑遇到重复会抛 `ConflictException` 中断；同步是批量场景，改为「跳过并计数」，避免一条重复导致整轮失败。

### 3.4 异步下发设计

与现有「批量执行」[execute_auto_cases](file:///d:/Users/zhangzhimin/Desktop/test01/fastapi-rbac/FASTAPI-RBAC/backend/app/services/plan_service.py#L473) 完全一致的模式：

```
接口线程：
  1. 校验项目存在、is_active、auto_root_path 已配置且目录存在可读  → 不满足直接 400
  2. asyncio.create_task(_sync_project_testcases(project_id))
  3. _running_tasks.add(task)  # 保持强引用，避免被 GC
  4. 立即返回 Response.success(message="已下发同步任务，请稍后刷新查看用例情况")
```

后台任务内部：

- 使用独立 `AsyncSessionLocal` 会话（不依赖请求会话生命周期）
- 加载项目 → 扫描解析 → 逐条校验/入库 → `commit`
- 结束时写一条汇总日志：`用例同步完成 project=1 新增=12 已存在=30 编码不合法=1 解析失败=0`
- 整体 `try/except` 兜底，异常只记 `logger.exception`，**不影响接口响应**（旁路任务）

进程模型说明：任务由接收请求的 gunicorn worker 执行（与现有后台执行一致）。因此**不做**进程内「该项目同步中」防抖（多 worker 下无效），重复点击最多导致第二轮全部「已存在」，无副作用；前端通过按钮 loading 避免误触。

### 3.5 接口定义

```
POST /api/v1/testcases/sync
权限：testcase:sync（JWT）
Body: { "project_id": 1 }

成功：{ "code": 200, "message": "已下发同步任务，请稍后刷新查看用例情况", "data": null }
失败：{ "code": 400, "message": "该项目未配置自动化根路径，无法同步" }
      { "code": 400, "message": "自动化根路径不存在: xxx" }
```

### 3.6 边界与异常

| 场景 | 处理 |
|---|---|
| 项目不存在 / 已停用 | 400，不下发 |
| 未配置 `auto_root_path` | 400，不下发（前端本就不显示按钮，防绕过） |
| 路径不存在 / 不是目录 | 400，不下发 |
| 目录下没有 `test_*.py` | 任务正常结束，日志记录「新增=0」，前端提示同步完成 |
| 文件语法错误 / 编码错误 | 跳过该文件，计入 `failed`，日志记录文件路径与原因 |
| 函数无 `@allure.title` | 标题回退为函数名 |
| 同一项目同名文件（不同子目录） | 先扫描到的入库，其余按 `(module_code, case_code)` 命中「已存在」跳过 |
| 子目录内用例 | 可同步入库，但平台执行按 `{auto_root_path}/{module_code}.py` 定位，需文件名与执行路径一致（见 §6） |

### 4.2 按钮显示条件

```js
// loadProjects：保留 auto_root_path，供显示条件判断
projectOptions.value = (res.data || []).map(p => ({
  label: p.name, value: p.id, auto_root_path: p.auto_root_path
}))

// 选中项目配置了自动化根路径才显示
const canSync = computed(() => {
  const cur = projectOptions.value.find(p => p.value === filters.project_id)
  return !!(cur && cur.auto_root_path)
})
```

```html
<a-button
  v-if="canSync"
  v-permission="'testcase:sync'"
  :loading="syncing"
  @click="handleSync"
>同步用例</a-button>
```

### 4.3 交互流程

1. 点击「同步用例」→ 按钮进入 loading 并去抖（防重复提交）
2. 调用 `POST /testcases/sync { project_id }`
3. 成功后 `message.success(后端返回的 message)`，提示「已下发同步任务，请稍后刷新查看用例情况」
4. 约 3 秒后自动 `loadData()` 刷新列表；用户也可手动「重置/查询」刷新
5. 失败（未配置路径/路径不存在等）直接展示后端错误信息

> 来源字段：同步入库的用例 `source = 自动同步`，当前页面筛选区没有「来源」筛选项，无需额外改动。

## 5. 权限与部署

### 5.1 部署步骤

1. 同步后端文件：`app/services/testcase_sync_service.py`（新增）、`app/api/v1/testcases.py`、`scripts/seed_data.py`
2. 执行 `python -m scripts.seed_data`（幂等补齐 `testcase:sync` 权限 + 「同步用例」按钮 + admin 授权）
3. 重启后端（`testcase_sync_service.py` 为新模块，必须重启）
4. 前端重新构建部署（`npm run build`）并刷新
5. **无 Alembic 迁移**，无需 `alembic upgrade`

### 5.2 验收要点

- 未选项目 / 项目无 `auto_root_path` → 按钮不显示
- 选中已配置项目 → 按钮显示；点击后立即返回提示（接口不阻塞）
- 等待几秒刷新：`tests/test_login.py` 的 3 个函数出现在用例列表，标题来自 `@allure.title`，模块编码=文件名、用例编码=函数名
- 重复点击同步：不产生重复用例，日志显示全部命中「已存在」
