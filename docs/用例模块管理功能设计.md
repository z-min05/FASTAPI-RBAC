# 用例模块管理功能设计文档

| 项 | 内容 |
|---|---|
| 文档版本 | v1.1 |
| 前置依赖 | 项目管理模块、用例管理模块、自动化用例文件生成模块、用例同步模块（均已完成） |
| 关联模块 | 用例执行（`plan_service`）、自动化文件生成、反向同步 |
| 文档日期 | 2026-09-14 |
| 说明 | 本模块把「用例模块」从**自由文本**升级为**项目内的多级树**，并让模块树与 pytest 的**目录/文件结构一一对应**；用例只能挂在末级模块上。 |

**v1.1 修订要点**

1. 模块 `code` 由「末级可空」改为**所有模块一律必填**；
2. 明确 **「能否挂用例」只由「该节点有无子节点」决定**，与 `code` 是否填写无关；
3. 明确 **文件按需生成**：创建用例时文件不存在则创建，已存在则只追加用例，不再有「无 `module_code` 所以不生成」的分支。

---

## 1. 需求概述

### 1.1 业务场景

- 在**用例管理**页左侧增加一个**模块树**，树本身支持**增删改查**（不再单独开菜单页）。
- 模块树按**项目**隔离：切换项目即切换整棵树。
- 模块可以**任意多级**，**每个模块都必须填写 `code`**（磁盘名）。
- **用例只能挂在末级（叶子）模块上**，非末级模块仅作为分组容器。
- **末级判定只看「有没有子节点」**，不看 `code` 填了什么。
- 模块树与自动化代码目录**一一对应**：
  - **非末级模块 → 文件夹**
  - **末级模块 → `test_xxxx.py` 文件**
- 创建用例时：**文件不存在就创建，已存在就只追加用例**。
- 相关的既有能力（文件生成、执行路径拼接、反向同步、导入导出）随之适配。

### 1.2 核心约束

| 规则 | 说明 |
|---|---|
| 模块 `code` 必填 | **所有模块（不论层级）都必须填 `code`**，作为磁盘上的目录名或文件名 |
| 末级 = 无子节点 | 「能不能挂用例」**只取决于该节点有没有子节点**，与 `code` 内容无关 |
| 用例只挂末级 | 创建/编辑用例时必须选中末级模块，后端强校验 |
| 末级 `code` 必须是文件名 | 末级模块的 `code` 需以 `test_` 开头（对应 `{code}.py`）；该校验在**创建/编辑用例**时执行（见 §3.1 说明） |
| 文件按需生成 | 创建/编辑用例时：文件**不存在则创建**（含多级目录），**已存在则只追加用例函数**，绝不覆盖既有内容 |
| 树按项目隔离 | 模块归属单一 `project_id`，跨项目不可见、不可移动 |
| 非末级不可挂用例 | 给已有用例的模块新增子节点会被拒绝（409） |
| 不自动搬迁磁盘文件 | 模块改名/移动后仅重算数据库中的路径，**旧文件不删除**（与现有「旧路径不删除，由用户手动清理」策略一致） |
| 删除非空模块被禁止 | 有子模块或挂有用例时返回 409，要求先清理 |

### 1.3 映射关系

```
projects.auto_root_path = /var/www/test_platform/test_project/meterbot/tests
        ↓
模块树                                    磁盘
────────────────────────────────────────────────────────────────
设备管理      (name, code=device)   →     device/            ← 文件夹（非末级，有子节点）
  ├─ 通信日志 (name, code=test_comm_log) → device/test_comm_log.py  ← 文件（末级，无子节点）
  └─ OTA     (name, code=test_ota)       → device/test_ota.py       ← 文件（末级）
组网          (name, code=network)  →     network/           ← 文件夹（非末级）
  └─ MESH    (name, code=test_mesh)      → network/test_mesh.py      ← 文件（末级）
        ↓
testcases.module_id     → 指向末级模块节点（权威来源）
testcases.module_code   → 模块相对路径 "device/test_comm_log"（由模块树推导，只读）
testcases.module        → 末级模块名称 "通信日志"（冗余，供列表/筛选/导出复用）
testcases.case_code     → pytest 函数名（仍由用户填写）
        ↓
执行路径 = auto_root_path + "/" + module_code + ".py"
```

> **关键点**：`testcases.module_code` **语义升级为「模块相对路径，不含 `.py`」**，列名保持不变。
> 这样 `plan_service`、`auto_file_service` 里既有的 `f"{module_code}.py"` 拼接逻辑**无需修改**即可支持多级目录。

### 1.4 本次确认的设计决策

| 决策点 | 结论 |
|---|---|
| 非末级模块（文件夹）命名 | **展示名与目录名分开**：节点有「模块名称」（展示）+「目录名/文件名」（磁盘，即 `code`） |
| 模块 `code` | **所有节点一律必填** |
| 末级判定依据 | **有无子节点**（与 `code` 无关） |
| 文件生成时机 | **创建/编辑用例时按需生成**：不存在则创建，已存在则追加 |
| 存量用例处理 | **自动迁移成节点并绑定**（按 `module_code` 自动建树 + 建「未分类」节点收纳无编码用例） |
| 是否需要独立菜单页 | **不需要**，模块树只嵌入用例管理页左侧 |
| 反向「同步用例」 | **按目录层级自动建树**，目录=非末级模块，`test_*.py`=末级模块 |

## 2. 数据模型

### 2.1 新表 `testcase_modules`

```sql
CREATE TABLE testcase_modules (
    id          SERIAL       PRIMARY KEY,
    project_id  INTEGER      NOT NULL REFERENCES projects(id)           ON DELETE CASCADE,
    parent_id   INTEGER      NULL     REFERENCES testcase_modules(id)   ON DELETE CASCADE,
    name        VARCHAR(50)  NOT NULL,              -- 模块名称（展示）
    code        VARCHAR(100) NOT NULL,              -- 磁盘名：目录名 或 末级为 pytest 文件名（不含 .py）
    description VARCHAR(500) NULL,
    sort        INTEGER      NOT NULL DEFAULT 0,
    created_at  TIMESTAMP    NOT NULL DEFAULT now(),
    updated_at  TIMESTAMP    NOT NULL DEFAULT now()
);

CREATE INDEX ix_testcase_modules_project_id ON testcase_modules(project_id);
CREATE INDEX ix_testcase_modules_parent_id  ON testcase_modules(parent_id);

-- 同一父节点下「模块名称」唯一
CREATE UNIQUE INDEX ux_testcase_modules_sibling_name
    ON testcase_modules(project_id, COALESCE(parent_id, 0), name);

-- 同一父节点下「目录名/文件名」唯一
CREATE UNIQUE INDEX ux_testcase_modules_sibling_code
    ON testcase_modules(project_id, COALESCE(parent_id, 0), code);
```

> **为什么索引里要写 `COALESCE(parent_id, 0)`**：PostgreSQL 中 `NULL` 互不相等，若直接用 `(project_id, parent_id, name)`，**多条顶级节点（`parent_id` 全为 NULL）不会互相冲突**，同级重名校验会失效。用 `COALESCE` 表达式索引把顶级节点统一映射为 `0` 才能正确约束。

### 2.2 `testcases` 表变更

| 字段 | 变更 | 说明 |
|---|---|---|
| `module_id` | **新增** `INTEGER NULL REFERENCES testcase_modules(id) ON DELETE SET NULL` | 权威归属；指向末级模块 |
| `module_code` | **语义变更**（列不变，`VARCHAR(100) NULL`） | 由「文件名」升级为**模块相对路径**，如 `device/test_comm_log`；由模块树推导，前端只读 |
| `module` | **语义变更**（列不变，`VARCHAR(50) NULL`） | 由「自由文本」改为**末级模块名称**的冗余快照，沿用现有列表/筛选/导出 |
| `case_code` | 不变 | pytest 函数名，仍由用户填写（可空） |

`ON DELETE SET NULL` 而非 `CASCADE`：删除模块受 409 保护，正常路径下不会触发；设为 `SET NULL` 可保证意外删除时**不丢用例数据**。

### 2.3 既有索引保持不动

`ix_testcases_project_module_code`（部分唯一索引 on `(project_id, module_code, case_code)` WHERE 两者均非空）**继续有效**：
由于 `module_code` 现在是**相对路径**，天然区分不同目录下的同名文件（如 `device/test_utils.py` 与 `network/test_utils.py`），语义依然正确，**无需重建**。

## 3. 关键规则

### 3.1 末级（叶子）判定

**末级 = 没有任何子节点的模块**。该状态是**动态的**，随增删子节点而变化。

| 状态 | 判定 | `code` 要求 | 能否挂用例 |
|---|---|---|---|
| **末级（叶子）** | 无任何子节点 | **必填**，且需以 `test_` 开头（如 `test_comm_log`），因为它对应 `{code}.py` 文件 | ✅ 可挂 |
| **非末级** | 有子节点 | **必填**，作为目录名（如 `device`），字符集 `^[A-Za-z0-9_\-]{1,100}$` | ❌ 不可挂 |

**`code` 的校验时机分两处**（这是本节最容易误解的点）：

| 时机 | 校验强度 |
|---|---|
| **创建/编辑模块节点** | 只校验**字符集与长度**（`^[A-Za-z0-9_\-]{1,100}$`），**不强制 `test_` 前缀** |
| **在该节点下创建/编辑用例** | 校验该节点**无子节点**（是末级）+ `code` **必须以 `test_` 开头** |

> 为什么要分开？因为**新建节点时必然还没有子节点**，但用户习惯**先建目录、再挂子模块**（先建「设备管理」、`code=device`，再往里加子模块）。若创建节点时就强制 `test_` 前缀，「先建目录」这条路就走不通了。
> 因此把 `test_` 前缀的强制点后移到「真正要当文件用」的时刻——即在它下面建用例时。此时若 `code` 不是 `test_` 开头，直接报错并提示改名（例如把 `device` 改成 `test_device`）。

### 3.2 校验正则（`auto_file_service.py`）

```python
# 模块 code：目录名/文件名通用字符集（创建/编辑模块时用）
ALLOW_MODULE_DIR_PATTERN  = re.compile(r"^[A-Za-z0-9_\-]{1,100}$")
# 末级模块 code：必须是 pytest 文件名（创建/编辑用例时用）
TEST_FILE_CODE_PATTERN    = re.compile(r"^test_[A-Za-z0-9_\-]+$")
# 模块相对路径：0..n 级目录 + 末级 test_ 开头的文件名（写入用例与拼路径时用）
ALLOW_MODULE_CODE_PATTERN = re.compile(r"^(?:[A-Za-z0-9_\-]+/)*test_[A-Za-z0-9_\-]+$")
# 用例函数名（不变）
ALLOW_CASE_CODE_PATTERN   = re.compile(r"^test_[A-Za-z0-9_]+$")
```

> 字符集里**不含 `.`**，因此 `..`、`./`、绝对路径、盘符天然无法通过，配合既有的 `_is_safe_path()` 复检形成双重防护。
> 原 `ALLOW_MODULE_CODE_PATTERN` 的报错文案「不能包含路径分隔符」需同步改为「模块路径格式不合法」（因为现在**允许** `/` 作为多级分隔符）。

### 3.3 模块 CRUD 规则

**创建 `POST /testcase-modules`**

1. `project_id` 项目必须存在且启用；
2. `parent_id` 为空 → 顶级节点；非空 → 父节点必须存在、**必须同项目**；
3. **`code` 必填**，校验字符集 `^[A-Za-z0-9_\-]{1,100}$`（**不强制 `test_` 前缀**，理由见 §3.1）；
4. `name` 不能包含 `/`（否则会破坏 CSV 的「模块路径」名称链语义）；
5. 同级 `name` 唯一、同级 `code` 唯一（应用层先查，给出友好提示；DB 索引兜底）。

**编辑 `PUT /testcase-modules/{id}`**

- 允许改 `name` / `code` / `description` / `sort` / `parent_id`；
- 改 `parent_id` 时校验：父节点同项目、**不能是自己或自己的子孙**（防环）；
- 改 `code` 时按当前节点状态（是否末级）重新校验：
  - 非末级 → 字符集校验；
  - **末级且该模块下已有用例** → 必须仍以 `test_` 开头（否则报错「该模块下有 N 条用例，文件名必须以 test_ 开头」）；
- 编辑成功后，**重算该节点子树下所有用例**的 `module` / `module_code` 并写回数据库；
- **不搬迁磁盘文件**（见 §3.5）。

**删除 `DELETE /testcase-modules/{id}`**

- 有子节点 → `409 ConflictException("该模块下还有 N 个子模块，请先删除子模块")`
- 挂有用例（直接挂载）→ `409 ConflictException("该模块下还有 N 条用例，请先移走用例")`
- 两者皆无 → 物理删除。

> **为什么不级联删除**：模块删除会连带影响磁盘上的目录/文件与测试计划引用，级联删除的破坏面太大且不可逆。改为「先清理再删除」，行为可预测。

### 3.4 给末级模块加子节点时的复检

由于「末级」是动态状态，给一个末级模块新增第一个子节点时它会变成非末级，此时后端复检：

- 该模块下**不能已有用例** → 若有用例返回 `409`「请先移走该模块下的用例，再把它作为分组目录」；
- `code` **不做额外要求**（必填是天然满足的；若原 `code` 是 `test_xxx`，它也符合目录名规则，允许保留，但前端提示「该目录名带 `test_` 前缀，建议改为普通目录名」，**不强制**）。

### 3.5 改名 / 移动对磁盘的影响（重要）

模块 `code` 变更或节点移动后：

- 后端**只重算数据库中的 `module_code`**；
- **不会重命名、移动、删除任何磁盘文件/目录**；
- 后续在「新路径」上保存用例时，会按需创建新目录与新文件（§3.6）；
- **旧路径下的文件保留**，需用户手动清理。

> 这与自动化文件生成模块既有约定完全一致（原文：*"若修改了 module_code 或 case_code，旧路径/旧函数不删除（由用户手动清理），仅在新位置生成"*）。前端在改 `code` 的确认弹窗中明确提示该后果。

### 3.6 路径推导与文件按需生成

**路径推导**

```python
def build_module_relpath(ancestor_codes: list[str], code: str) -> str:
    """ancestor_codes: 从根到自身的父节点的目录名链
    返回 POSIX 风格相对路径，如 'device/test_comm_log'"""
    return "/".join([c for c in ancestor_codes if c] + [code])
```

- 求祖先链：从目标节点沿 `parent_id` 向上回溯到根，**深度上限 32 层**（防脏数据造成死循环）；
- 由于 `code` 必填，相对路径**恒非空**。

**文件按需生成**（创建/编辑用例时）

```
文件路径 = auto_root_path / {module_code}.py
    ├─ 目录不存在 → mkdir(parents=True, exist_ok=True)   ← 多级目录一次建好
    ├─ 文件不存在 → 创建文件，写入 import pytest / import allure 头部
    │                （若填了 case_code，紧接着写入用例函数）
    └─ 文件已存在 → 只追加用例函数（两个空行分隔）
                     · 同名函数已存在 → 静默跳过，返回「函数已存在，跳过生成」
                     · case_code 为空 → 文件已存在时不做任何改动
```

**权威实现已存在于 `generate_automation_file()`**，本次只需：

1. 把其中「`module_code` 和 `case_code` 都非空才生成」的门槛改为「**`auto_root_path` 非空即可生成**」（`module_code` 现在恒非空；`case_code` 为空时只建文件骨架，不再整体跳过）；
2. 其余逻辑（`mkdir(parents=True)`、`function_exists` 判重、追加不覆盖）**完全复用**。

**生成失败不阻断用例保存**：沿用现有策略——失败时仅返回提示信息，用例照常入库（现有实现即如此，见 `_generate_auto_file` 返回 `{generated, message}`）。

## 4. API 接口设计

新增路由前缀 `/testcase-modules`，注册于 `app/api/v1/__init__.py`。

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/testcase-modules/tree?project_id=` | `testcase:list` | 取整个项目的模块树 |
| GET | `/testcase-modules/{id}` | `testcase:list` | 节点详情 |
| POST | `/testcase-modules` | `testcase:module:create` | 新建节点 |
| PUT | `/testcase-modules/{id}` | `testcase:module:update` | 编辑节点 |
| DELETE | `/testcase-modules/{id}` | `testcase:module:delete` | 删除节点 |

> 读接口复用 `testcase:list`：模块树与用例列表是**同一个页面**，若单独要求 `testcase:module:list`，只有读权限的用户会看到「有列表没树」的割裂界面。

### 4.1 树节点响应结构

```json
{
  "id": 12,
  "project_id": 3,
  "parent_id": 5,
  "name": "通信日志",
  "code": "test_comm_log",
  "description": null,
  "sort": 0,
  "is_leaf": true,
  "module_path": "device/test_comm_log",
  "case_count": 4,
  "total_case_count": 4,
  "children": []
}
```

| 字段 | 说明 |
|---|---|
| `is_leaf` | 无子节点 |
| `module_path` | 相对路径（不含 `.py`），恒非空 |
| `case_count` | **直接**挂在本节点的用例数（非末级正常为 0） |
| `total_case_count` | 含子树的用例总数（用于树节点右侧计数展示） |

排序：同级按 `sort ASC, id ASC`。

### 4.2 请求体

```python
class TestCaseModuleCreate(BaseModel):
    project_id: int
    parent_id: int | None = None
    name: str = Field(..., min_length=1, max_length=50)
    code: str = Field(..., min_length=1, max_length=100)   # 必填
    description: str | None = Field(None, max_length=500)
    sort: int = 0

class TestCaseModuleUpdate(BaseModel):
    name: str | None = Field(None, min_length=1, max_length=50)
    code: str | None = Field(None, min_length=1, max_length=100)
    description: str | None = Field(None, max_length=500)
    sort: int | None = None
    parent_id: int | None = None   # 显式传 null 表示移到顶级
```

### 4.3 用例列表接口变更

`GET /testcases` 新增两个参数：

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `module_id` | int | null | 按模块筛选 |
| `include_children` | bool | true | 是否包含子模块下的用例（默认包含，这样点非末级节点也能看到整棵子树） |

实现：`include_children=true` 时先递归收集子树的 `module_id` 集合，再 `TestCase.module_id.in_(ids)`。

> 原有的 `module`（名称精确匹配）筛选参数**保留**以兼容外部调用，但前端将改用 `module_id`。

### 4.4 用例创建 / 编辑接口变更

`POST /testcases`、`PUT /testcases/{id}`：

1. 新增必填字段 `module_id`；
2. 后端校验链路：
   - 模块存在 → **同项目** → **是末级（无子节点）**（否则 400「只能选择末级模块」）
   - 末级模块的 `code` **必须以 `test_` 开头**（否则 400「该模块将作为 pytest 文件使用，请把目录名改为 test_ 开头，如 test_device」）
3. 服务端**自动推导并覆盖**写入 `module`（= 末级模块 `name`）与 `module_code`（= 相对路径），**忽略前端传来的这两个值**；
4. `case_code` 仍由前端填写（**可空**）；
5. 落库后**无条件调用** `_generate_auto_file()`：
   - 门槛由「`auto_root_path` + `module_code` + `case_code` 三者非空」改为「**`auto_root_path` 非空**」（`module_code` 已恒非空）；
   - 于是：文件不存在 → 创建；文件已存在 → 只追加用例；`case_code` 为空 → 只创建文件骨架；
   - 生成失败**不阻断**用例保存，仅返回提示。

## 9. 数据迁移

迁移文件：`alembic/versions/0008_testcase_modules.py`

```
revision      = "0008_testcase_modules"
down_revision = "0007_project_code_init"
```

### 9.1 结构变更

1. `create_table("testcase_modules", ...)` + 2 个普通索引 + 2 个唯一表达式索引；
2. `op.add_column("testcases", sa.Column("module_id", sa.Integer(), nullable=True))`；
3. `op.create_foreign_key("fk_testcases_module_id", "testcases", "testcase_modules", ["module_id"], ["id"], ondelete="SET NULL")`；
4. `op.create_index("ix_testcases_module_id", "testcases", ["module_id"])`。

### 9.2 存量数据回填（按项目遍历）

对每个 `project_id`：

**A. 有 `module_code` 的用例**（按 `module_code` 分组）

1. `module_code.split("/")` → `dirs`（前半段）+ `leaf_code`（最后一段）；
2. 逐级 `get_or_create` 目录节点（`code = 目录段`、`name = 目录段`）；
3. `get_or_create` 末级节点：
   - `code = leaf_code`
   - `name` = 该组内**最小 id 用例**的非空 `module` 值；若为空则取 `leaf_code`
4. 回填 `testcases.module_id`，并把 `module_code` 归一化为 `"/".join(parts)`（保证格式统一，符合「恒等于树推导值」的不变量）。

**B. `module_code` 为空的用例**

- 若该项目存在此类用例 → `get_or_create` 一个末级节点 `{name: "未分类", code: "test_uncategorized"}`（`code` 必填，且末级需 `test_` 开头）；
- 回填 `module_id`，并把 `module_code` 一并回填为 `test_uncategorized`，**维持「`module_code` 恒等于树推导值」的不变量**；
- `module` 字段保持原值不动（若无值则填「未分类」）。

> **需明确告知的副作用**：这些用例在迁移前 `module_code` 为 `NULL`，是不可自动化执行的；迁移后 `module_code` 变成 `test_uncategorized`，**若它们同时填了 `case_code`，就会变为「可尝试执行」**。但此时磁盘上 `test_uncategorized.py` 尚未生成，首次执行会因文件不存在而失败。解决办法很自然：在该模块下保存任意一条用例（或用模块树的「＋用例」）时，文件会按 §3.6 自动补建。
>
> 若你希望**完全不改变这批用例的可执行性**，可改为「只回填 `module_id`、`module_code` 保持 `NULL`」，代价是出现少量「`module_code` 与树推导值不一致」的历史数据。此项列为待确认点（§16）。

### 9.3 回滚

```
drop_index ix_testcases_module_id
drop_constraint fk_testcases_module_id
drop_column testcases.module_id
drop_table testcase_modules   （连同索引）
```

> 回滚不恢复已被归一化的 `module_code`（`device/test_x` 不会被拆回 `test_x`），也不恢复被回填的 `test_uncategorized`；如需严格回滚需另行备份。文档中标注为**已知限制**。

## 12. 边界与异常

| 场景 | 处理 |
|---|---|
| 用例选了非末级模块 | `400 只能选择末级模块` |
| 用例的末级模块 `code` 未以 `test_` 开头 | `400 该模块将作为 pytest 文件使用，请把目录名改为 test_ 开头，如 test_device` |
| 用例的模块不属于所选项目 | `400 模块不属于该项目` |
| 给有用例的末级模块加子节点 | `409 请先移走该模块下的用例，再把它作为分组目录` |
| 移动节点到自己的子孙下 | `400 不能移动到自身的子模块下` |
| 同级 `name` 重复 | `409 同级已存在同名模块` |
| 同级 `code` 重复 | `409 同级已存在相同目录名` |
| `code` 为空 | `400 目录名/文件名不能为空` |
| `code` 含 `/`、`..`、盘符、绝对路径、中文 | `400 格式不合法`（正则已拦截，`_is_safe_path` 兜底） |
| `code` 超长（>100） | `400 长度不能超过 100` |
| 删除有子模块 / 有用例的模块 | `409`，提示剩余数量 |
| 末级模块下保存用例但文件已存在且同名函数已存在 | 静默跳过，返回「函数已存在，跳过生成」 |
| `auto_root_path` 未配置 | 模块树 CRUD **不受影响**（不写磁盘）；用例保存成功，但不生成文件（返回空提示，沿用现有行为） |
| 磁盘目录不可写 | 用例保存成功，返回「自动化文件生成失败: 权限不足...」提示，**不阻断保存** |
| `case_code` 为空 | 文件不存在 → 生成仅含头部的文件骨架；文件已存在 → 不做改动 |
| 祖先链存在脏数据 / 深度 >32 层 | 路径推导返回截断结果并记警告，不抛异常 |

## 15. 验证要点

**需在真实环境执行的端到端验证（本机无法完成，需 Linux 侧配合）**

1. `alembic upgrade head` 在 PostgreSQL 上实际执行并通过；
2. 存量数据回填结果抽查：模块树层级、`module_id` 绑定、`module_code` 归一化、「未分类」节点生成；
3. 建三级模块 → 在末级建用例 → 检查 `auto_root_path/一级/二级/test_xxx.py` 是否按需生成；
4. 同一末级模块下**再建一条用例** → 确认文件**只追加函数、不覆盖**已有内容；
5. 给「先建目录」场景验证：新建 `code=device` 节点 → 在其下建用例 → 确认报错并提示改名；
6. 修改中间层模块 `code` → 确认数据库路径更新、旧文件保留；
7. 删除非空模块 → 确认 409 与提示文案；
8. 反向同步：在磁盘上新建 `tests/newdir/test_foo.py` → 同步 → 确认模块树与用例均已建立；
9. 权限隔离：`user` 角色登录 → 树可见、增删改按钮不可见。

**可在本机完成的静态/单元级验证**

- 路径推导 `build_module_relpath` 的多级 / 深嵌套场景；
- 三个正则的边界（`..`、绝对路径、中文目录名、空值被拒；`device` 通过 MODULE_DIR 但不通过 TEST_FILE_CODE）；
- 子树 `module_id` 收集与深度限制；
- 迁移链 `0001 → … → 0008` 线性无冲突。

## 16. 待确认点

| 项 | 结论 |
|---|---|
| 是否支持拖拽调整模块顺序/层级 | **本期不做**，改 `sort` 字段 + 「上级模块」下拉实现调整 |
| 建模块时是否在磁盘创建空目录/空文件 | **不创建**（避免路径未配置或不可写时阻断模块管理，也避免产生空目录）。文件一律在**保存用例**时按需创建 |
| 模块改名是否搬迁磁盘文件 | **不搬迁**，仅重算数据库路径并提示用户（与既有策略一致） |
| 是否需要模块级用例批量移动 | 本期不做，列为后续扩展 |
| 模块树是否显示用例数 | 显示（`case_count` 直接挂载数、`total_case_count` 子树合计） |
| 是否允许跨项目移动模块 | **不允许** |
| `case_code` 为空时是否也创建文件骨架 | **创建**（符合「末级模块即文件」的模型）；若你希望「没填用例编码就不动磁盘」，请告知，可改回 |
| 存量 `module_code` 为空的用例迁移后是否回填为 `test_uncategorized` | **回填**（保持「`module_code` 恒等于树推导值」的不变量）；副作用与替代方案见 §9.2 |
